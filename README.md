# mcp-vs-cli

**What does an MCP server cost you in context, and what do you get back for it?**

Connecting an MCP server can put every one of its tool schemas into the request before the model has
read a word of your task, and most servers hand back whole response objects once it starts working.
Give the agent a CLI instead and it starts from nothing — but it spends turns discovering what the
CLI can do.

That trade gets argued about constantly and measured rarely. This repo measures it against a real
public API, live, inside an agent harness people actually use.

## The arms are installations, not code paths

Every trial runs inside [pi](https://pi.dev), a stock coding agent. Every arm gets the same
objective, the same settings and unrestricted `bash`. What differs is only what a user *installed*
beside it:

| arm | what was installed |
| --- | --- |
| `baseline` | nothing — a shell, and the API's own error messages to learn from |
| `mcp` | an MCP server exposing the 78 operations |
| `cli` | a compiled binary on `PATH` |

This is the second design. The first measured exposure inside a loop written here, which made every
quirk of that loop a confound — and did, four separate times ([arm-symmetry](.claude/reference/arm-symmetry.md)).
Running inside a harness nobody here controls removes that whole class of error, at the price of no
longer controlling when the harness loads tools. That price is stated rather than hidden.

Both installables are **generated from the same OpenAPI document**, so a difference between arms is a
difference of exposure and never of capability — enforced by tests that compare the surfaces
operation by operation and parameter by parameter.

**The subject.** [Dados Abertos da Câmara dos Deputados](https://dadosabertos.camara.leg.br/swagger/api.html),
the Brazilian Chamber of Deputies' open-data API: OpenAPI 3.0.1, 78 operations across 11 tag groups,
no authentication, real relational data. Chosen for size and for obscurity at the record level — a
model cannot answer *which deputy filed which bill* from memory, so the arms have to use the tools.
The document is vendored under [`data/specs/`](data/specs) with source URL, fetch date and sha256; it
does not validate, which is a fact about the subject and is reported rather than fixed. The API's
*responses* are not vendored anywhere: nothing is cached, and ground truth is solved live in the same
window as the trial it grades.

## Static result

What each way of exposing 78 operations occupies before the task is read (`o200k_base`), from
`bun run measure`:

| operations | mcp, every schema | mcp, with projection | cli manual | cli index |
| ---: | ---: | ---: | ---: | ---: |
| 5 | 666 | 865 | 1,040 | 360 |
| 20 | 3,948 | 4,745 | 5,912 | 1,942 |
| 78 | **16,295** | 19,416 | **23,746** | **7,386** |

Offering a projection parameter on every tool costs 3,121 tokens — the honest price of advertising
the capability.

**The most useful number here is one that changed when the code did.** The CLI manual was 16,737
tokens while its help text was hand-rendered; generated by commander it is 23,746, 42% more. The
earlier version was quietly flattering the CLI arm, and the README had to carry a caveat saying so.
It does not any more, because the help is now the ecosystem's rather than ours.

## Run-time result

**None yet.** Every previously published figure was measured by the harness this repo no longer has,
or against a corpus it no longer keeps, and all of them are withdrawn. Reproducing them under the new
design is the next piece of work.

## Findings withdrawn

Listed because a benchmark that publishes only what held up is not reporting, it is advertising.

- **"Blind tool search costs 4× an index."** An artifact of a search that returned five full schemas
  per keyword guess.
- **"An upfront index costs twice a lazy search."** The mechanism is real, but the measurement came
  from a round trip the harness forced on a model that had read the index correctly.
- **Every run-time number.** They came from a hand-written loop and, earlier, a recorded corpus.
  Neither exists now.
- **Every static number for the CLI.** Its help was hand-rendered and 42% cheaper than a real CLI
  framework's.

Most were found by reading traces rather than by reasoning about the code.

## Reproduce

The static half needs no network and no key:

```bash
bun install && bun run measure
```

The run-time half reaches the live API and needs an [OpenRouter](https://openrouter.ai/keys) key in
`.env` (see `.env.example`):

```bash
bun run build:cli
bun run ground-truth
bun run run-arms t1-civil-name
```

Quality gate:

```bash
bun run check
```

## Method notes

- **Names.** The spec's own `operationId`s are unusable as tool names (`search`, `listar`,
  `listar_1`). Every artifact gets names from one mechanical transform over method and route, applied
  identically so it cannot favour a format. Resource nouns stay in the API's own Portuguese.
- **The ecosystem over our own code.** `$ref` resolution, seeded sampling, HTTP retry, CLI help and
  jq are libraries. Not tidiness: anything hand-written is a thing that can be accidentally tuned,
  and the CLI help proved it.
- **Both filtering paths get the same language.** Real jq, via WebAssembly, on both sides — so the
  comparison is about where filtering happens rather than which syntax the model knows.
- **Compaction and retries are off.** pi compacts context automatically, and its own context estimate
  goes null after a compaction until a fresh assistant response. Left on, the benchmark would measure
  pi's compactor and lose its metric exactly when it mattered.
- **Nothing is read from the machine.** Settings and session are in memory, the system prompt is
  overridden, and discovery of extensions, skills, prompt templates and context files is off. An
  earlier attempt that inherited the operator's own configuration carried about 29,000 extra tokens
  of context per turn.
- **Errors are data.** `/votacoes/{id}/votos` answers 400 to `itens`, and recovering from that is
  half of what one task measures.

## Caveats

- **Choosing a harness chooses a disclosure level.** pi's MCP support surfaces a server through a
  proxy rather than as N schemas; other harnesses declare everything on connect. The axis this
  project studies separates two shipped products, so results are about pi's defaults and say so.
- **Two arms can receive different data.** With nothing cached, the API can move between one trial
  and the next. Not prevented; measured.
- **A past run cannot be re-executed by anyone, including us.** Auditing survives — the numbers come
  from the provider's own usage — but re-collection does not. That is the price of not keeping a copy
  of someone else's data.
- **Repeats are missing.** Two runs of an identical arm on an identical task have differed by a whole
  turn. Nothing should be read as a difference smaller than that until repeats are in.
- **Familiarity favours the CLI.** Models have read enormous amounts of `--help` and `| jq`. Part of
  what "CLI" measures is prior exposure. Not removable inside the experiment — and arguably a real
  advantage rather than an artifact.
